# SupplyRadar Growth Loop

## Objective

Prove that SupplyRadar can turn existing market demand into activated supplier users without founder-led begging or manual prospecting.

## Smallest complete loop

`DETECT -> SCORE -> PUBLISH -> DISCOVER -> CAPTURE -> DELIVER -> OBSERVE -> LEARN -> REALLOCATE -> REPEAT`

### 1. DETECT
Find real UK procurement and pre-procurement signals in the current wedge: MUGA, outdoor gym, playground, artificial pitch and sports-facility supply.

### 2. SCORE
Score both commercial relevance and acquisition value. Only publish when the signal gives a supplier useful context beyond a copied notice.

### 3. PUBLISH
Strengthen durable category/buyer pages with verified live signals, early-warning context and official-source links. No generic SEO articles.

### 4. DISCOVER
Target existing high-intent demand. Search, AI discovery, links and useful public data are preferred. Founder outreach is not the default acquisition channel.

### 5. CAPTURE
One CTA: **Get relevant opportunities matched to my company.** Preserve landing page and acquisition-source attribution in every request.

### 6. DELIVER
Produce the first company-specific Radar quickly enough that the supplier experiences the core value before any product build is required.

### 7. OBSERVE
Track: qualified discovery -> CTA/request -> Radar delivered -> response/open/click where observable -> repeat request -> willingness to pay.

### 8. LEARN
Ask which categories, pages, signals and decision labels create qualified activation. Traffic alone is not success.

### 9. REALLOCATE
Expand only clusters with evidence. Fix weak conversion before adding traffic. Park clusters with neither discovery nor activation after a credible test.

### 10. REPEAT
New market signals update acquisition assets; user behaviour updates the product and scoring model.

## Gates

- No dashboard/accounts/backend until repeat usage or payment evidence earns them.
- No speculative features while activation is unproven.
- No mass page generation without unique decision-useful intelligence.
- Every public claim needs provenance.
- Every acquisition asset must have one measurable next action.
- Founder effort should seed the machine, not remain the machine.

## Current primary experiment

**Cluster:** MUGA / outdoor gym

**Acquisition surface:** `/tenders/muga/`

**Pass evidence:** qualified strangers discover the page and request a company-specific Radar.

**Strong signal:** repeat Radar request, unsolicited request for regular delivery, referral/forward, or willingness to pay.

**Failure diagnosis:**
- no impressions/discovery -> distribution/indexing/query problem
- discovery but no CTA -> proposition/page problem
- CTA but no completed request -> capture friction
- requests but no repeat -> product/value problem
- repeat but no WTP -> monetisation/value-capture problem

## Expansion order

MUGA -> playgrounds -> artificial pitches -> sports facilities.

Expansion is evidence-earned, not calendar-driven.
